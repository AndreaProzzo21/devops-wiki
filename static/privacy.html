Privacy & policies

Last updated: 21 October 2026

DevOps Command Wiki is a read-only reference for command-line tools. There are no accounts, no ads and no analytics scripts run by this site. This page explains what little data is involved and the rules for using the service.

1. What we process

  • Searches and page requests. The text you type in the search box and the pages you open are sent to the server to return results.
  • IP address. Used to apply rate limits (see section 5). The application keeps it in memory only for that purpose.
  • Server logs. The web server and the infrastructure in front of it may record request metadata (time, path, query string, status code, network address) for operations, troubleshooting and abuse prevention, kept only for as long as needed for those purposes.

We do not ask for names, emails or any other personal information to use the site, and we do not sell or share data for advertising.

2. Cookies and local storage

This site does not set cookies. It stores your light/dark theme choice in your browser's local storage (devopswiki-theme). That value stays on your device and is never sent to the server. You can remove it at any time by clearing the site data in your browser.

Because the site is delivered through Cloudflare, Cloudflare may set strictly necessary security cookies (for example for bot protection) as described in its own policy.

3. Third parties

  • Cloudflare provides DNS, caching, DDoS protection and the secure tunnel to the server, so it processes your requests as an intermediary. See the Cloudflare privacy policy.
  • GitHub Pages hosts the API documentation linked in the header and footer. When you open it you leave this site and the GitHub privacy statement applies.

4. Your rights

If you are in the European Economic Area you have the right to access, rectify or erase personal data we hold about you, to restrict or object to its processing, and to lodge a complaint with your data protection authority (in Italy, the Garante per la protezione dei dati personali). Given how little data is processed, requests are usually answered by pointing to the sections above, but you are welcome to write to the contact address below. The processing described here is based on our legitimate interest in running and securing the service.

5. Fair use and rate limits

The site and its API are free to use, including from scripts, within reasonable limits. Requests are rate limited per IP address and excess requests receive an HTTP 429 response. Please do not scrape the service at high volume, probe it for vulnerabilities without permission, or try to bypass the limits. We may block abusive traffic without notice.

6. Disclaimer

Commands, flags and examples are provided for information only, as-is and without warranty of any kind. Tools change between versions, and some commands are destructive (for example deleting resources, pruning data or force-pushing). Always read the official documentation, test in a safe environment and double-check the target (cluster, namespace, account, environment) before running anything in production. We are not liable for any loss or damage resulting from the use of this content.
